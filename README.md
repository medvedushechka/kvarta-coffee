# Кварта — лендинг обжарки кофе

Тестовое задание: [tz.vitai.world](https://tz.vitai.world/).

Next.js 16 / TypeScript / CSS Modules / Zod / PostgreSQL (Supabase). Без корзины и онлайн-оплаты. Форма отправляет заявку менеджеру для последующего звонка; база хранит заявки.

## Локальный запуск

Требуется Node.js 20.9+.

```bash
npm install
npm run dev
```

Откройте http://localhost:3000. На Windows PowerShell с запретом сценариев используйте `npm.cmd` вместо `npm`.

## Настройка формы и деплой

1. Создайте проект Supabase. Запустите SQL из `supabase/schema.sql` через SQL Editor.
2. Скопируйте `.env.example` в `.env.local` и заполните `SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY` (секретный ключ — **только на сервере**, не `NEXT_PUBLIC_`).
3. Добавьте эти же переменные в настройках проекта Vercel, задеплойте репозиторий.
4. Установите `NEXT_PUBLIC_SITE_URL` как адрес опубликованного сайта для метаданных. Протестируйте реальную отправку заявки на опубликованном сайте.
5. Менеджер просматривает заявки в Supabase Table Editor (`public.kvarta_leads`). Не публикуйте таблицу или ключи.

Без настроенного Supabase endpoint отвечает HTTP 503 — заявки **не** имитируются и **не** теряются молча.

## Особенности

- Телефон нормализуется до `+375XXXXXXXXX`, принимаются распространённые белорусские мобильные коды 25/29/33/44. Этот упрощённый валидатор не проверяет существование номера и не охватывает стационарные номера.
- Дедупликация 10 минут — SQL-функция с транзакционным advisory lock по телефону. Повторная заявка не сохраняется даже при одновременных запросах.
- UTM-метки, gclid/yclid/fbclid, первый URL и referrer сохраняются в sessionStorage и передаются вместе с URL отправки. Это клиентская атрибуция, которую нельзя считать криптографически достоверной.
- Для конструктора используются сгенерированные иллюстрации ингредиентов. Упаковки каталога сделаны средствами CSS; это концепт, а не существующий товар.
- Социальное preview имеет SVG-изображение; поддержка SVG некоторыми мессенджерами ограничена. При необходимости конвертируйте `public/og.svg` в PNG и поменяйте metadata.

## Работа с ИИ

Заготовка для честного заполнения исполнителем: указать, какие части были сгенерированы ИИ, какие были проверены и изменены вручную, обнаруженные ошибки, ограничения и что осталось неготовым. Не заявлять о тестах, которые ещё не проводились.


## Интерактивный конструктор

Первый экран содержит конструктор из пяти ингредиентов (эспрессо, вода, молоко, сироп и пенка). До шести условных слоёв, анимация наливания, сброс, распознавание напитков и готовые рецепты с автосборкой. Условные слои не заменяют точные миллилитровые пропорции напитков. Конструктор не создаёт заказ и не заменяет форму заявки. При `prefers-reduced-motion: reduce` анимация наливания отключается.

## Приёмочные проверки формы (обязательно выполнить после настройки Supabase)

1. Отправить валидную заявку и убедиться, что в `public.kvarta_leads` появилась ровно одна строка.
2. Повторить сразу с тем же номером (другой формат записи телефона тоже считается дублем): количество строк не увеличивается.
3. Отправить два одновременных POST с одним номером: одна строка, второй ответ `duplicate`.
4. Проверить ошибки для `+375 99 123-45-67`, пустого имени и недопустимого типа заявки.
5. Открыть `/?utm_source=instagram&utm_campaign=trial&utm_content=ad42`, заполнить форму и проверить `attribution`, включая `landingPage`, `submissionPage`, `referrer`.
6. Временно удалить ключ доступа к базе на тестовом окружении: должен появиться 503 и понятное сообщение, без ложного успеха.
7. На опубликованном Vercel-сайте повторить первый тест и проверить результат в Supabase.

Ключ `SUPABASE_SERVICE_ROLE_KEY` нельзя помещать в репозиторий, HTML или переменные `NEXT_PUBLIC_*`. Доступ к записям ограничен сервером, но таблица содержит персональные данные: необходимо ограничить круг сотрудников с доступом к Supabase и определить срок хранения данных.
